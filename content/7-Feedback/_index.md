# Sharing and Feedback

Participating in the **Workforce Bootcamp - First Cloud AI Journey (FCAJ)** program gave me an opportunity to better understand how cloud knowledge can be applied to a practical product. Through learning, hands-on practice, and project development, I gained a broader perspective on building applications on AWS and identified several areas that could be improved to make the experience more effective for future participants.

The following comments are based on my personal experience and perspective.

## 1. Positive Aspects of the Program

### Learning Content Combined with Hands-on Practice

Learning about AWS services and applying them to a project made the concepts easier to understand than studying theory alone. While developing Smart Kitchen, I had the opportunity to see how the frontend, APIs, backend, database, and supporting services connect and work together within one system.

### Opportunities for Independent Learning and Experimentation

The practical activities encouraged me to read documentation, review configurations, and find ways to address issues that arose during implementation. This was valuable because it helped me develop independent research habits instead of relying entirely on pre-defined instructions.

### A Practical Final Project

Building a specific product gave the learning process a clear objective. Tasks such as frontend deployment, API development, data storage, location search, and exploring AI integration allowed me to connect several concepts from the program within one problem.

## 2. Challenges I Encountered

- **A broad range of learning topics:** AWS offers many services, each with its own configuration, limitations, and pricing model. For beginners, it can sometimes be difficult to determine where to start and how deeply each topic should be studied.
- **Time-consuming troubleshooting:** An issue may be caused by IAM permissions, API configuration, input data, or service quotas. Without experience in reading logs and tracing application workflows, identifying the root cause can take considerable time.
- **Estimating costs during early development:** Some services charge based on requests, data transfer, usage duration, or consumed resources. Learners need guidance on how to monitor costs from the beginning of a project.
- **Keeping project documentation synchronized:** When configurations or architecture change, guides, diagrams, and deployment information also need to be reviewed so that the documentation remains consistent with the actual system.

## 3. Suggestions for Improving the Program

1. **Provide a progressive hands-on learning path:** Organize the content from foundational concepts to complete deployment, with clear learning outcomes and required knowledge for each stage. This would help beginners follow their progress and identify knowledge gaps.
2. **Add verification checklists after each lab:** In addition to configuration instructions, provide validation steps such as checking service status, testing API calls, reviewing logs, and confirming stored data. Checklists would help learners understand what successful completion looks like.
3. **Include more realistic troubleshooting scenarios:** Introduce common situations such as missing IAM permissions, API errors, incorrect CORS settings, mismatched data, or service quota limits. Each scenario could explain how to narrow down the cause rather than simply providing a sample configuration.
4. **Integrate cost management and security from the beginning:** Show learners how to configure budget alerts, review Billing, clean up resources after practice, and apply the IAM least-privilege principle.
5. **Schedule progress and architecture reviews:** Short review sessions at key milestones could help learners identify design issues early and avoid extensive changes near the end of a project.
6. **Standardize documentation and evidence requirements:** Provide clear checklists for the proposal, workshop, architecture diagram, demo video, and final report. This would help learners prepare in advance and ensure that submitted materials accurately reflect the implementation status.

## 4. Expectations for Future Programs

I hope future programs will continue combining foundational knowledge with project-based practice. In addition to introducing services, more examples of design decisions, common errors, service limitations, and cost evaluation would help learners understand how to approach real-world cloud problems.

I would also welcome more opportunities for technical discussions and project presentations at different stages. Receiving feedback while a project is still in development would help learners make timely adjustments and improve their ability to explain their technical decisions.

## 5. Acknowledgements

I appreciate the opportunity to participate in FCAJ and gain hands-on experience with AWS services. The program helped me recognize both the knowledge I have acquired and the skills I still need to improve. I would like to thank the organizing team, mentors, and everyone who shared their knowledge and provided support, motivating me to continue learning and developing in the cloud computing field.
